FULL MYSQL Secure API Architecture
Version: 7.0.107 Single-Service Edition

Current runtime:
- Public 4-module Web App: Quick Check, Ordering, Dumping, Price Change
- Operations Overview dashboard
- Dumping Pending + resolved/superseded history
- Price Change what-if analysis + audited proposal workflow
- Admin Console with Admin ID + Password and signed HttpOnly browser session
- Config-driven Ordering Policy engine and Suggested Order Qty
- Final Order workflow: Recommendation -> Draft -> Confirmed -> Marked Submitted -> History
- API and background worker aligned to 7.0.107-single-service

Final Order safety:
- Only positive ORDER_RECOMMENDATION_READY items can be added to a Draft.
- Drafts are grouped by next order date + next delivery date.
- Final quantity can be adjusted only while workflow_status=DRAFT.
- Confirmed orders are no longer editable.
- MARKED_SUBMITTED is an internal audit state only; it does not transmit an order to any supplier.
- Every line snapshots Suggested Qty, Effective OH, 7D velocity, DOS, price, policy, and publish lineage.

Admin authentication:
- Browser login: FULLMYSQL_ADMIN_LOGIN_ID + FULLMYSQL_ADMIN_PASSWORD or FULLMYSQL_ADMIN_PASSWORD_HASH.
- Password is never stored in browser localStorage/sessionStorage.
- Browser session is HttpOnly, Secure, SameSite=Lax and same-origin protected for writes.
- Legacy admin API Bearer tokens remain supported for PowerShell / API clients.

Safety / authority:
- Public App does not require login.
- Missing Ordering policy remains POLICY_NOT_CONFIGURED; quantity is not guessed.
- Price proposal execution marking does not directly mutate authoritative live retail price.
- No RAW mutation.

Version: 7.0.148 Single-Service Edition

v7.0.147 QA HOLD Delete No-Body Fix:
- QA HOLD delete endpoint no longer accepts or validates a JSON request body.
- Two-click confirmation remains entirely in the Web UI.
- Backend still restricts deletion to raw-stage QA_HOLD batches and preserves downstream lineage when needed.
- Public Web App HTML now sends no-store/no-cache headers plus X-FULLMYSQL-Version so stale browser HTML cannot keep an old delete contract.
- This removes FastAPI request-body validation as a possible HTTP 422 source.


v7.0.146 QA HOLD Delete 422 Fix:
- Replaced the delete endpoint's implicit dict body with an explicit Pydantic request model.
- Eliminated the unresolved Any annotation from api.py.
- Delete confirmation body is now validated as {confirm: string}.
- Frontend API error handling now displays FastAPI validation details instead of only HTTP 422.
- Existing two-click delete confirmation, hard-delete, and lineage-preserving hide behavior remain unchanged.


v7.0.145 Deleted QA Batch Visibility Fix:
- Fixed Recent Uploads filtering for history_hidden batches using explicit JSON string comparison.
- After successful delete/hide, the batch card is removed immediately from the current page.
- A client-side deleted-batch set prevents the same batch from reappearing during subsequent refreshes in the same session.
- Backend history filtering remains authoritative across page reloads.
- Existing two-click delete confirmation and lineage-preserving delete behavior remain unchanged.


v7.0.144 QA HOLD Delete Reliability:
- Replaced browser-native confirm popup with a visible two-click confirmation inside the batch card.
- First click changes the button to Confirm Delete Batch <id>; second click performs the API request.
- Delete success or failure is shown directly on the same batch card.
- Duplicate provenance now only references prior files from QUICK_CHECK_READY / QUICK_CHECK_READY_WITH_HOLDS batches with Phase 3 history.
- Raw-stage QA_HOLD files are no longer valid duplicate authorities for future uploads.
- If an old QA_HOLD batch is already referenced by a later file, Delete removes it from Upload History while preserving underlying lineage.
- If no later references exist, the eligible raw-stage QA_HOLD batch is hard-deleted.
- READY and downstream Phase2C/Phase3 batches remain protected from deletion.


v7.0.143 QA HOLD Batch Deletion:
- Recent Uploads now shows Delete QA HOLD Batch only for raw-stage QA_HOLD batches.
- Deletion is blocked if Phase 2C, Phase 3, or any downstream pipeline stage exists.
- READY / successful batches cannot be deleted through this path.
- Browser confirmation plus an exact backend confirmation token is required.
- Eligible deletion removes raw rows, ingest errors, ingest columns/sheets/files, RAW_INGEST pipeline history, and the batch record.
- This is intended for failed upload batches such as an unclassified source that never entered downstream processing.


v7.0.142 OH Upload Classification Repair:
- Standalone OH filename tokens are recognized as on_hand, including OH-*, OH_*, and OH <date> naming.
- Fixes files such as oh-092826.xls being incorrectly classified as unclassified.
- Duplicate suppression now requires the same SHA to have been successfully INGESTED under the same resolved source type with zero errors.
- A previous unclassified / QA_HOLD copy no longer blocks corrected re-ingest of the same bytes.
- Existing historical QA_HOLD batches remain preserved for audit; re-uploading the corrected file creates a new valid batch.


v7.0.141 Upload History Timestamps:
- Recent Uploads now shows each batch Uploaded date/time.
- Completed batches also show Completed date/time.
- Each raw file in upload history shows its own actual upload_timestamp.
- Existing source type, row count, coverage range, duplicate status and ingest status remain visible.


v7.0.140 Reports + Search:
- Reports now has three tools: Report, Price Change, and Uploads.
- Performance Report no longer exposes a category selector; it runs on the full Seafood scope.
- Report Date Top Sellers is capped at 20 and rendered as a compact sales list with Sales$, Qty, and Avg Sold Price.
- Performance response includes an approximately 200-word narrative analysis anchored to the selected report date.
- Price Change Suggestions moved to a separate Reports subpage.
- Uploads remains a separate Reports subpage with all existing no-login upload/readiness tools.
- Bottom main navigation icons, labels, and touch targets were enlarged for mobile readability.
- Fixed MySQL 8 fuzzy-search fallback failure caused by DISTINCT with ORDER BY a.article_id; fallback now orders by selected fields.
- Typo-tolerant item search remains enabled, including SALMOM -> SALMON style matching.


v7.0.139 Google Apps Script analysis bridge:
- Preferred FULL MYSQL -> FULL_MYSQL_CHATGPT_ANALYSIS transport is now APPS_SCRIPT.

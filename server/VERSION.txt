Version: 7.0.40 Single-Service Edition
Fix company-report Cost UOM parser and repair poisoned derived Cost-UOM observations.

Production evidence from v7.0.39:
- 53 rows were OFFICIAL_COST_UOM_UNSUPPORTED
- 66 affected Families had unsupported official Cost-UOM evidence
- source_cost_uom_token_counts contained numeric values such as 5.952380952...,
  3.375, 23.5, 41.666666..., etc.
- those values are monetary cost values, not UOM tokens
- official_repairable_family_count=0

Root cause:
- _process_company used substring header matching for Cost UOM aliases
- generic alias "Unit" could match header "Unit Cost"
- the numeric Unit Cost value was therefore stored as cost_uom_code

Changes:
1) Future company-report ingestion:
   - Cost UOM uses strict exact header matching only
   - supported exact header names include Cost UOM, Cost Unit,
     Cost Unit of Measure, Cost Base UOM, UOM, UM, Unit of Measure
   - generic substring matching is disabled for Cost UOM
   - exact header "Unit" is intentionally not accepted because it is ambiguous
2) Historical derived repair:
   - re-reads immutable RAW company-report headers/rows
   - recalculates company_price_observation.cost_uom_code from strict explicit headers
   - if no explicit Cost-UOM header exists, derived cost_uom_code becomes NULL
   - reconciles existing official article_cost_observation rows:
     unsupported/missing UOM -> SUPERSEDED
     supported explicit UOM -> synchronize/reactivate
3) safe-cost-refresh:
   - performs this deterministic derived Cost-UOM cleanup inside the same transaction
   - then re-runs the read-only cost-hold diagnostic
   - only the post-cleanup truly-safe subset is targeted
   - all existing identity/target/regression rollback guards remain active

No RAW mutation.
No schema migration.
No inferred Cost UOM.
No Base/Inventory UOM inference.
No cross-UOM conversion inference.

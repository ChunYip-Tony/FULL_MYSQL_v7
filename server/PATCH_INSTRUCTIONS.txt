FULL MYSQL v7.0.35 GitHub Patch

Purpose:
- Fix MySQL error 1305: SAVEPOINT confirmed_uom_refresh does not exist.
- Preserve atomic rollback semantics for maintenance and Phase 3 publishing.

Root cause:
- apply_manual_upc_overrides/apply_manual_upc_retirements called table-ensure helpers.
- Those helpers always issued CREATE TABLE IF NOT EXISTS.
- MySQL DDL implicitly commits the active transaction, which destroys SAVEPOINTs.
- A failed v7.0.34 run may therefore have committed some manual override/UOM rows
  before the later Quick Check rebuild rolled back.

Recovery design:
1) Keep the 22 exact user-confirmed Selling UOM overrides.
2) Table ensure-functions first check information_schema and skip DDL when present.
3) confirmed-uom-refresh ensures bootstrap tables before transaction start.
4) Close the bootstrap/read transaction.
5) Start one explicit transaction.
6) Reapply all manual authority idempotently.
7) Resolve prior per-UPC core-hold rows for the serving batch.
8) Rebuild Quick Check.
9) Run product-identity audit.
10) Verify all 22 target Selling UOMs.
11) Commit only if all checks pass; otherwise rollback the entire business transaction.

Phase 3:
- manual authority tables are ensured before its explicit transaction begins
- v7.0.30 fail-closed Quick Check SAVEPOINT is preserved from implicit DDL commits

After deploy:
1) Verify /healthz = 7.0.35-single-service.
2) Re-run POST /v1/maintenance/confirmed-uom-refresh with the same confirmation body.
3) Confirm status=COMMITTED.
4) Confirm target_count=22 and remaining_missing_selling_uom=0.
5) Re-run product-identity audit.
